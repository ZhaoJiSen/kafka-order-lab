# 订单跨语言消息 Demo

本项目用订单理解 PHP → Kafka → Java → Kafka → PHP 的真实跨语言消息。

本次实现选择 Laravel 13 / PHP 8.4、Spring Boot 3.5.16 / Java 21。优先在本机运行 PHP、Java 和前端，Kafka 可连接已有实例；也保留整套 Docker 配置。具体安装步骤以根目录 README 为准。

## 业务过程

PHP 接收下单请求，将订单和 OrderCreated 待发送事件存入同一 SQLite 事务。独立 PHP Outbox 进程发送到 demo.orders.created。Java 消费组读取订单事件，按金额不超过 1000 元通过、超过 1000 元拒绝的教学规则审核；审核与 OrderReviewed 待发送记录存入同一 H2 事务。Java 定时发送结果到 demo.orders.reviewed。PHP 消费结果，事务中保存事件处理记录并更新订单，然后提交消费位置。浏览器轮询 PHP API 获取订单状态。

两个 Topic 各三个分区，每端一个常规消费者。两端发送时以 orderId 为 Key。每条消息使用 eventId 去重，correlationId 跟踪同一订单，source 标明 php-orders 或 java-review；订单创建事件的 version 为 1。业务字段位于 data。Java 返回的 inputRecord 保存其实际收到的来源 Topic、Partition、Offset、Key。

## 实现取舍

为了直接学习客户端行为，PHP 使用 php-rdkafka 包装成小的发送服务和 Artisan 消费命令；Java 使用 Spring Kafka。没有引入 Kafka HTTP 代理或用 HTTP 回调替代跨语言消息。PHP 页面只通过 HTTP 调用 PHP，PHP 与 Java 通过 Kafka 协作。

数据库分别采用 SQLite 和 H2，减少部署依赖；不要求安装 MySQL。本例每个数据写入服务按单实例运行，不提供多副本数据库共享能力。金额使用整数分。演示不包含真实支付、库存扣减、登录或生产风控。

## 失败与一致性

数据库事务和 Kafka 写入没有合并成全局事务。Outbox 用持久化待发送记录覆盖业务已保存但消息未发送的窗口；写入确认后标记发送，如果标记前故障，消息仍可能重复。两端消费者通过 eventId 和业务修改同事务来识别重复，业务完成后再提交 Offset。Java 还检查订单已审核、PHP 检查订单终态，避免新事件编号的旧创建/结果把已完成订单改回待审核。

审核是本地数据库操作，没有外部通知等不可回滚副作用。扩展真实业务时还需要下游幂等、死信、告警、安全、schema 演进、多实例并发和故障演练；不能将此 Demo 视为生产级 exactly-once 保证。Kafka 为单节点、单副本，本例不演示节点容灾。

## 验收

以真实 Kafka 验证审核通过、拒绝；暂停 Java 或 PHP 结果消费者时 PHP 保持等待；恢复后完成；重复下单请求复用订单；重发原始事件不重复审核或生成结果；回退消费组位置后重读不回滚数据库；容器重启保留订单与去重记录。页面与日志显示实际消息元数据。
